# @zhiqiangme/dsh-magpie

在 DSH「插件」页管理 Magpie 提供的模型，并把选中的模型写入 DSH 的 **Magpie** 模型分组。模型清单、名称、勾选、顺序、上下文、输出限额、图片输入和思考档位都由本插件保存。也可以从侧边栏左上角的 **Magpie** 入口打开同一张卡片（见「侧边栏入口」）。

可在卡片下载或升级 Windows 版 Magpie（升级时自动退出正在运行的 Magpie）；DSH 启动时若本机没有 Magpie 在运行，按所选方式在后台启动，默认使用网页模式（无托盘）。标题栏按钮按方式打开默认浏览器或程序窗口；可自动开启 Magpie 的轻量模式、在卡片切换防止休眠，可选退出 DSH 时关闭本机 Magpie。插件不迁移或卸载旧 OpenCode 插件。

## 卡片布局

- **标题栏**：网关状态（按已保存的地址每 15 秒检查一次 `/api/hello`）、已安装的 Magpie 版本（有新版本时提示，点击跳到「更新」页），以及按启动方式显示的「打开 Magpie 网页」或「打开 Magpie 窗口」。
- **模型**：搜索、「从 Magpie 同步」「手动添加模型」、全选、排序（按模型排序、按供应商排序）与分类筛选（按模型分类、按供应商分类），以及模型列表。
- **开关**：「同步到 DSH」「自动路由」默认开启；小上下文屏蔽可选「不屏蔽」「低于 200K」「低于 500K」，默认低于 500K；「屏蔽不支持图片的模型」默认关闭。
- **渠道**：显示因余额不足而当天停用的渠道，提供「恢复选择」。北京时间每天 04:00 自动恢复；充值后可提前手动恢复，恢复不改变模型清单与勾选。
- **连接**：网关地址、API 协议、网关 Key 与「检查连接」。
- **偏好**：Magpie 程序（启动方式、启动时打开、退出时关闭、每日重新获取模型并同步）、Magpie 设置（自动开启轻量模式、防止休眠）、DSH（侧边栏入口）。
- **更新**：Magpie 程序的下载与升级、程序路径，以及插件自身更新。
- **底栏**：保存状态、「重新载入 / 放弃更改」和「保存并同步」，切换标签页时始终可见。

## 安装

从本仓库源码安装：先完全退出 DSH（包括托盘），在仓库根目录执行：

```powershell
.\install-plugins.cmd --action install --plugins magpie --profiles desktop --yes
```

或者使用 DSH 自带的插件管理器：

```powershell
dsh plugin --profile desktop add "file:<仓库绝对路径>\dsh-magpie"
```

npm 发布后可用 `dsh plugin --profile desktop add @zhiqiangme/dsh-magpie`。源码依赖是拷贝，更新源码后请重新运行安装脚本。

## 插件自身更新

「更新」页下半部分的「插件更新」管理 `@zhiqiangme/dsh-magpie` 的版本，与上半部分的「Magpie 程序」分开。

- 显示当前运行版本与 npm 最新版本。由宿主并行查询 npm 官方源和 npmmirror，取成功响应中的最高版本；成功结果缓存十分钟，点击「检查更新」可强制刷新。
- 一键更新使用 DSH 官方 `pluginManager.listVersions/updateBundle`。先用 `listBundles` 核对安装来源和本插件的 `updatable`，再用 `listVersions` 选最新的兼容、未弃用正式版，把精确版本和同一注册表交给 `updateBundle`。兼容性检查、锁、安装与失败时恢复旧版都由宿主处理。卡片展示核对、卸载、安装、恢复阶段，只有实际安装版本等于目标版本才显示成功。恢复失败或连接中断会提示去「插件」页核对。
- 宿主在卸载步骤报 `bundle-in-use`（热重载后本插件仍在运行，DSH 拒绝卸下）时，没有安装新版本，旧版照常运行，卡片直接说明并给出指定版本重装入口。宿主此时已把本插件移出 `dsh.profile.bundles` 且不撤回，卡片会用 `setBundleEnabled` 补回，否则下次启动不再加载；补回失败时提示手动重新启用。
- 宿主缺少官方更新接口时，可升级 DSH 或复制 `@zhiqiangme/dsh-magpie@版本号` 手动安装。在「插件」页本插件详情里先关闭「Magpie 模型管理」组件，再卸载，通过「添加插件」安装指定版本，装好后重新打开该组件。保留插件数据即可沿用原有配置。
- `listVersions` 每次要在宿主上跑一串 `pnpm view`，所以 npm 显示已是最新时不去列，列过的结果按已装版本缓存十分钟；「检查更新」两者都绕过。宿主的插件管理器每完成一次操作都会广播变更（包括在官方插件页里更新本插件），卡片据此静默重读实际安装状态。
- 有新版本却没有一键更新时才说明原因：`file:` / `link:` 本地目录安装需更新源码并重新运行安装脚本；由 DSH 统一管理的安装随宿主更新。官方判定不可更新或没有兼容版本时，不提供指定版本绕过入口。
- 设置页的两处卡片与侧栏页面共用一份更新状态。整页刷新或插件热重载后重新读取运行版本与实际安装状态。
- 模型有未保存更改或当前操作未完成时，先保存或放弃更改、等待操作结束，再更新插件。更新成功后按宿主结果提示重启 DSH。

## 侧边栏入口

支持侧栏页面的 DSH 会在左上角「插件」和「自动化任务」之间显示 **Magpie** 入口，点击后在主区域打开与插件设置相同的管理卡片。「偏好」页提供以下侧边栏入口选项。

- **自动**（默认）：模型清单为空时显示，方便首次配置；保存至少一个模型后隐藏。只看清单是否有模型，不看是否勾选同步。
- **显示** / **隐藏**：不论清单如何。

选择后立即生效；「自动」模式按已保存的清单判断，模型增删在「保存并同步」或「从 Magpie 同步」后才影响入口。正在查看 Magpie 页面时入口不会立刻收起，切换到其它页面后再按设置隐藏。入口隐藏后仍可在「插件」页打开卡片；没有侧栏页面的旧版 DSH 只保留插件页卡片。

## 哪些改动立即生效

卡片上的开关和分段选项（启动方式、启动时打开 Magpie、退出时关闭 Magpie、每日重新获取模型并同步、自动开启轻量模式、防止休眠、侧边栏入口、同步到 DSH、自动路由）改完立即保存，不需要点「保存并同步」，也不会带上卡片里尚未保存的其他改动。启动方式供下次启动或升级重启使用，不会中断正在运行的实例；其余选项即时生效。连接设置（网关地址、API 协议、Key）、Magpie 程序路径和模型清单（增删、编辑、勾选、排序）仍需点击「保存并同步」。

## 启动方式与打开 Magpie

「偏好 › Magpie 程序 › Magpie 启动方式」提供两项，未设置的旧配置也默认使用网页模式：

- **网页**（默认）：运行 `magpie serve --web`，后台提供网关和 `http://127.0.0.1:3430/` 管理页，无托盘，也不自动弹浏览器。标题栏的「打开 Magpie 网页」会确认网页服务并在默认浏览器中打开带登录信息的页面；尚未运行时先启动并等待就绪。网页不嵌入 DSH。
- **托盘**：后台运行 `magpie tray`。标题栏的「打开 Magpie 窗口」运行 exe，通过 Magpie 的单实例交接唤出原窗口；未运行时打开窗口。

切换后立即保存，下次启动、升级后重启和升级失败后的恢复启动都遵循所选方式。已有实例不会被强制结束；若刚切换至网页且旧实例未开启浏览器访问，按钮会提示退出 Magpie 后重新启动，不会另起第二份程序。两种方式都需要先下载并验证程序。

插件将随机网页密钥保存到宿主凭据库的 `DSH_MAGPIE_WEB_KEY`，仅通过子进程环境变量 `MAGPIE_WEB_KEY` 交给 Magpie，不写入插件配置或返回状态；已有 `MAGPIE_WEB_KEY` 时优先沿用。它与网关 API Key 独立。已运行的桌面实例若开启了浏览器访问，插件可读取其本机 `web-page.json`，打开该实例的实际端口和链接。

## Magpie 设置：轻量模式与防止休眠

这两项直接读写 Magpie 自己的设置文件（`~/.config/magpie/settings.json`；设置了 `XDG_CONFIG_HOME` 时在其下），与 Magpie「设置 › 常规」中的同名选项相同，只改这几个字段。Magpie 第一次运行后才会生成该文件，之前这两项不可用。运行中的 Magpie 保存自己的设置前会重新读取文件，外部改动不会被覆盖（本机实测）。

- **自动开启轻量模式**（默认打开）：DSH 启动时，以及插件下载、升级或打开 Magpie 前，把 Magpie 的轻量模式设为开启：窗口关闭约一分钟后释放界面内存，网关和后台任务照常运行。取消勾选后插件不再改动这项设置，不会替你关闭它。
- **防止休眠**：关闭、开启、屏幕也常亮三档，选择后立即写入 Magpie 设置。

## 启动 DSH 时打开 Magpie

「偏好」页的「启动 DSH 时打开 Magpie」默认开启。插件激活时（DSH 启动、插件更新后重新加载）先检查本机：Magpie 端口已有服务应答，或已有 `magpie.exe` / 官方 Windows 产物名的进程（包括另装的 Magpie）在运行，都不再启动；否则以独立进程按所选方式打开「Magpie 程序路径」中的程序，不弹出窗口或浏览器。程序必须能验证为 Magpie，未下载、无法验证、正在下载升级或网关地址不是本机时跳过。取消勾选后，下次启动 DSH 不再自动打开。

网页模式使用的 `magpie serve --web` 在同一进程中提供网关和管理页，可以在浏览器查看该进程的实时路由，无需另起桌面窗口。

## 退出时关闭 Magpie

「偏好」页的「退出 DSH 时关闭 Magpie」默认关闭，打开即生效。开启后，正常退出 DSH 时结束本机目标 Magpie，包括托盘进程；停用、卸载或更新本插件不会触发关闭。

指定了「Magpie 程序路径」时只处理该完整路径的进程；未指定时，优先识别占用本机 Magpie 端口、文件名为 `magpie.exe` 或官方 Windows 产物名的进程，未找到则检查插件独立目录。远程 Magpie 不会被关闭，不按进程名称批量结束。Windows 之外暂不支持此联动；强制结束 DSH 进程无法保证执行退出回调。

退出时先中止并等待正在进行的程序任务，避免升级收尾在清理后又启动 Magpie。下载或升级后启动的 `magpie-bun.exe` 子进程也会随目标主程序关闭；网关由 Bun 监听时，先沿父子关系识别对应的 Magpie 主程序。清理限定到该实例，其他实例共用同一路径的 Bun 运行时也不受影响。

## 下载与升级 Magpie

在「更新」页的「Magpie 程序」点击「检查更新」或「下载 Magpie」。已安装时显示当前版本和「升级 Magpie」；下载期间显示进度。下载或升级完成后自动按所选方式以独立进程启动：网页模式在后台启动；托盘模式首次下载打开窗口供配置，升级后只在托盘启动。DSH 退出不会连带结束它（除非开启「退出 DSH 时同时关闭 Magpie」）；若该程序已在运行则不重复启动，启动失败只提示原因、不影响安装结果。

升级正在运行的 Magpie 时，插件先下载并校验新版本，替换前才结束目标程序（包括托盘进程及其插件宿主子进程），尽量缩短网关不可用的时间；正在进行的请求会中断。无法结束时不替换、提示手动退出；结束后若替换失败，插件会在后台重新打开原程序。

- 默认安装到 `<DSH_HOME>/magpie/backend/current/magpie.exe`，未指定 `DSH_HOME` 时使用 `~/.dsh`。`Magpie 程序路径` 可填写已有 exe 的绝对路径，留空恢复独立目录；通过「保存并同步」保存路径偏好。程序操作立即作用于填写的路径，但不会保存或覆盖模型草稿。
- 下载中断后自动续传：连接 30 秒无数据即断开，从已下载的字节继续请求，最多尝试 5 次；仍失败时保留部分文件，再次点击「下载 Magpie」或「升级 Magpie」接着下载。部分文件以预期 SHA-256 命名，放在 `<DSH_HOME>/magpie/cache/downloads`，换了 Release 不会续到旧文件上；校验不符时删除并从头下载，安装成功后删除。
- 使用官方 [`yetone/magpie-releases`](https://github.com/yetone/magpie-releases/releases) 的最新正式版，选择完整 GUI 产物 `magpie-windows-amd64.exe` / `magpie-windows-arm64.exe`。使用 GitHub 提供的 SHA-256 digest，缺少时读取同一 Release 的 `SHA256SUMS`；无有效校验值则拒绝安装。`GITHUB_TOKEN` / `GH_TOKEN` 可提高版本查询额度，界面不返回 token。
- 下载、校验与暂存版本验证通过后才替换；升级后再次验证，失败自动恢复旧文件。旧版备份放在 `<DSH_HOME>/magpie/backend/versions`，每个目标保留最近三次成功升级的备份。并发安装通过操作锁保护，插件关闭取消下载。Magpie 自己的账号、插件和设置目录不会迁移或清理。
- 下载升级目前支持 Windows x64 / ARM64；其他平台的模型管理照常使用。开发和测试可用 `DSH_MAGPIE_BACKEND_ROOT` 单独指定程序管理根目录。

### 自动更新 Magpie 程序

「更新」页的「自动更新 Magpie 程序」默认开启，开关立即保存。后台任务随插件启动，无需打开管理页面：启动约 10 秒后首次检查，之后每 5 分钟检查官方最新正式版。按 Release 的 `published_at` 计算，发布满 30 分钟才下载；已发现的新版本会在冷却时间到期时再次检查。缺失或无效的发布时间不会自动升级，未来时间继续等待。

下载和 SHA-256、程序版本校验可以在对话运行时进行。完成后，检查宿主所有工作区及子代理：全部空闲才退出目标 Magpie、替换 exe 并按所选方式重新启动；有对话运行、执行工具或等待审批，或宿主运行状态暂不可用时，保留已校验文件，每 5 秒重试空闲检查。手动升级同样在替换前等待对话空闲，但不受 30 分钟发布等待限制。

自动更新只处理已保存路径中能识别版本的本机程序，不自动首次安装、不降级；关闭插件总开关、关闭自动更新、切换远程网关或更改已保存程序路径后，尚未开始替换的自动任务会取消。下载失败保留断点缓存，后续检查重试；手动与自动升级共用安装锁、校验、备份与回滚。停用插件会停止计时并中止等待。界面显示下载、校验、等待对话空闲及升级结果。

## 每日重新获取模型

「偏好」里的「每日重新获取模型并同步」默认开启。以北京时间每天 **04:00** 为新一天开始，首次启用或当天尚未完成时，在启动约 15 秒后检查；所有工作区和子代理均空闲才执行，状态服务尚未就绪则继续等待。DSH 未运行时不执行，下次启动补做当前日的一次刷新，不补跑所有错过的日期。等待或失败后每 5 分钟重试，临近 04:00 时按每日边界唤醒，与电脑时区无关。

依次调用 Magpie 网页自身的「重新获取模型」接口，只刷新 Magpie 中已开启且允许获取模型列表的渠道，不开启已关闭渠道，不调用「测试模型」或发送对话。需使用本机 Magpie，并开启它的网页访问（插件默认网页启动方式已满足）；沿用现有网页密钥登录，不创建新密钥或打开浏览器。一个渠道失败不阻止其它渠道刷新；各渠道当天成功的进度写入插件缓存，重启或重试时跳过已成功的渠道。

刷新后读取网关目录，并按宿主锁内最新配置同步到插件和 DSH：保留已有模型的勾选、显示名、顺序及手工条目，暂时从目录消失的模型也保留；更新已知能力，新发现的模型追加到末尾且默认不勾选。遵守「同步到 DSH」的现有开关，不强制打开。目录为空或格式异常时保留原清单。DSH 同步失败时继续重试，不重复获取当天已成功的渠道。整个任务不重启 Magpie 或中断正在输出的对话。

「偏好」显示等待、刷新、失败重试或今日完成状态。完成后点「重新载入」可查看最新清单；已打开页面的未保存草稿不会被后台状态轮询覆盖，旧草稿保存仍经过版本冲突校验。缓存 `daily-models.json` 仅保存业务日期、渠道 ID 和完成时间，不保存账号、网页密钥或 Cookie。

## 模型管理

1. 在插件卡片的「连接」页填 Magpie 地址，默认 `http://127.0.0.1:3425`，选择调用协议。
   点击「从 Magpie 同步」会立即用当前 Magpie 目录覆盖保存清单并更新 DSH，无需再次点击保存。
2. 点击「手动添加模型」，填写 Magpie 可识别的完整 ID，例如 `workbuddy-ai/deepseek-v4.1-flash` 或路由组 ID。显示名称可留空。
3. 模型列表左侧勾选，显示名称右侧箭头展开详细配置；详情在列表原位展开，后续模型自动下移。按需编辑 ID、名称、上下文、输出限额、图片输入和思考档位，例如 `low, high, max`。思考档位只能使用 DSH 支持的 `off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`，且不能只有 `off`；不支持思考的模型留空。未知能力留空，不按模型名称猜测。
4. 勾选模型，拖动勾选框左侧的六点手柄调整顺序，打开「同步到 DSH」，点击「保存并同步」。选中的模型按清单顺序出现在 **Magpie** 分组（provider ID 仍为 `dsh-magpie`）。

点击「从 Magpie 同步」后，结果会显示「本次导入新增 N 个模型」或「本次导入没有新模型」，并保留 DSH 分组数量或同步失败原因。新增按同步前已保存的完整清单比较模型 ID；筛选、名称更新、勾选、草稿增删和 DSH 同款合并不影响统计，同步目录的重复 ID 只计一次。

模型行右侧的徽标依次显示「不支持图片」、渠道、上下文；支持图片输入的模型省略图片提示。渠道名称与「按供应商分类」一致；`codearts`、`doubao-work`、`qwenwork` 分别显示为 `CodeArts`、`DoubaoWork`、`QwenWork`。未知渠道显示 ID 中的供应商前缀，没有前缀的路由组显示「未指定供应商」。详情中的「支持图片输入」勾选仍用于编辑实际能力。

「开关」页的「屏蔽不支持图片的模型」默认关闭，开启后只显示输入能力包含图片的模型，可与上下文屏蔽、搜索及分类筛选取交集。开关即时保存，只影响卡片列表，不更改模型勾选、完整清单、DSH 同步或自动路由；批量勾选与排序仍只作用于当前可见模型。

管理列表会在模型名后追加供应商简称，例如 `DeepSeek V4.1 Flash WorkBuddy`、`Step-5-Preview WorkBuddy GL`、`DeepSeek V4.1 Flash Free OpenCode`。写入 DSH 模型列表的名字去掉独立的 `Free` 标签，再做连字符化：模型本名内的空格换成 `-`，与供应商简称之间保留空格（如 `LongCat-2.5 OpenCode`）；开启自动路由时，条目直接使用模型本名（如 `DeepSeek-V4.1-Flash`），不再拼接 `Auto` 或供应商简称，实际出口由路由决定。插件卡片内的管理显示仍保留空格。`workbuddy-ai` 为国际版，显示为 `WorkBuddy GL`；`workbuddy` 为国内版，显示为 `WorkBuddy`。Qoder / Trae 国际版同样使用 `GL`。名称已带对应简称时不重复追加；手工名称、模型 ID 与排序保持不变，未知供应商或路由组不追加简称。

`DeepSeek-Flash`、`Deepseek-V4.1-Flash` 等写法统一显示为 `DeepSeek V4.1 Flash`，保留 `Free`、`(Max)` 等尾缀和供应商简称；中文「预览版」（含括号写法）统一显示为 `Preview`，展示名默认不出现中文；搜索、快捷排序、分类与 DSH 模型名称同步使用这一显示规则。此规则仅派生显示名称，不改写保存的名称或模型 ID，其他 DeepSeek 版本不受影响。

支持搜索、全选、取消全选、删除和离线编辑。批量勾选只影响当前搜索和分类筛选结果。保存只写 DSH 配置，不要求 Magpie 正在运行；模型 ID 是否可用，取决于 Magpie 和上游实际支持。

当前勾选和已保存勾选组成列表置顶区，各自内部保持原有排序。新勾选会立即置顶；取消一个已保存勾选后，该行暂时留在原位，点击「保存并同步」并保存成功后才取消置顶，避免勾选时行突然移动。新勾选如果尚未保存就撤销，则直接回到未置顶区。置顶只影响卡片展示，不会另改写入 DSH 的清单顺序。

### 自动路由

同步到 DSH 的显示名称统一去掉独立的 `Free` 标签，例如 `LongCat-2.5-Free` 显示为 `LongCat-2.5`，`MiniMax-M3.1-Flash-Free` 显示为 `MiniMax-M3.1-Flash`。当前不显示倍率或 token 单价；`Free` 不能代表包含多个出口的自动组都免费。此规则只影响 DSH 显示名称，卡片中的上游名称、原始模型 ID、自动条目 ID 与已有模型引用保持不变。

`Seed-Evolving` 是已确认的无版本号具体型号，普通、`-auto`、`-max` 和 `-auto-max` 出口按相同显示名归入一条 `auto:seed-evolving`。只合并已勾选出口，不会自动勾选其余条目；旧版拆分后生成的哈希或数字后缀引用会在同步时迁移并去重。无版本号名称只对已确认型号开放，`search_agent_qwen_fast` 等通用内部别名继续保留独立组。

`-auto` 路由后缀（包括 `-auto-max` 中的 Auto）按同款处理，如 `GLM-4.7` 与 `glm-4.7-auto` 合并。`Seed-2.1-Pro`、`Doubao-Seed-2.1-Pro` 与「豆包 2.1 Pro」是已确认的同款别名，统一归入 `auto:seed-2.1-pro`。原始出口 ID 仍用于转发，合并后的旧模型引用会自动迁移；`fast` /「高速」代表不同价格的独立版本，不移除其后缀或并入普通版。

「自动路由（同款模型合并）」默认开启，开关立即保存并同步。开启后，裸模型 ID 相同的已选出口合并为一条 `auto:` 条目，不会把 DeepSeek、GLM 大系列里的不同型号混在一起。月日快照后缀（如 `-1017`）和明确的 `free` / `std` 档位不算型号差异；Preview（含中文「预览版」）与非 Preview 型号独立分组，例如 `Qwen4-Max` 与 `Qwen4-Max-Preview` 分别生成两个 DSH 条目，只在各自的同款渠道之间切换；ID 与名称任一处带 Preview 标记都属于预览版，中文、英文及括号写法归为同一预览版。推理档位标记 `(Max)` 仍不算型号差异（带 `(Max)` 与不带后缀的同款合并）。ID 是别名（如 `frontier-1`、`qmodel_latest`、`dfmodel`）看不出同款时，按带版本号的显示名归组（Preview / 预览版归一后比较）；不带版本号的通用别名（如 `search_agent_qwen_fast`）同名也不按名称合并，避免误并不同模型。其它不同 ID 不猜测合并。

条目 ID 直接取实际模型名（小写连字符形式），不再出现内部别名：`auto:qwen4-max-preview`、`auto:kimi-k3.1-pro`、`auto:longcat-2.5-free`、`auto:seed-evolving`；DSH 模型列表里的名称同样是模型本名（`Qwen4-Max-Preview`、`Kimi-K3.1-Pro`），不再拼接 `Auto` 或供应商简称。同一组内取出现最多的写法作为 ID，避免清单顺序变化导致 ID 变动；单个候选也使用同一规则。不同模型恰好同名时（例如两个 `search_agent_qwen_fast`），ID 在模型名后追加由候选原始 ID 派生的稳定哈希，展示名按出现顺序加 `2`、`3`；重排不会让候选互换 ID，取消或删除候选也不会把它的旧引用复用给同名模型，旧数字后缀引用会自动迁移。名称是占位符（如 `-`）时退回裸模型 ID。修改显示名或切换开关会把 DSH 中已有的旧 `auto:` ID（含别名 ID 和大小写不同的写法）迁移到新 ID。

自动路由按模型 ID 的供应商前缀识别渠道，国内版和国际版分别处理。同一供应商的额度目录有多个可识别的订阅账号时，各账号独立参与选路，例如 WorkBuddy 的两个账号各占一个渠道。选中后，插件把 `X-Magpie-Account` 发给 Magpie 网关，网关按该账号发送，且不会向供应商传这个请求头。没有可用账号目录的渠道继续由 Magpie 选号。账号拆分发生在请求路由中，DSH 模型列表仍按模型显示。

首次选路及每隔一小时后的下一次选路读取 Magpie `/v1/magpie/quotas`。各渠道取自己仍有余额的最近一批积分到期时间 `runsOutAt`，只考虑 `runsOut > 0` 且尚未到期的批次。负载相同时优先到期早的渠道，无到期数据的排在后面。到期时间相同或都未知时，按清单中供应商首次出现的顺序及网关返回的账号顺序排列。周期重置 `resetsAt`、套餐期限和预计用完时间都不参与积分到期排序。

每轮首次选路先比较各渠道被多少个其它运行中的对话占用，再以当前到期及失败顺序打破平局。同一轮内，后续模型请求（包括工具调用后的继续推理）优先沿用本轮渠道，负载或到期顺序变化时仍沿用。渠道故障时按原有规则尝试其它出口，成功切换后，本轮后续请求优先用新渠道。选路仍按模型、图片、思考档位和渠道停用状态筛选候选。

同一对话不重复计数，也不把自己作为竞争对话。执行工具期间仍保留占用，轮次结束、停止或取消时释放。新一轮优先空闲渠道；对话数超过渠道数后，按各渠道一个、两个、三个依次均衡分配。例如 A 已被对话 a 占用，新一轮对话 b 优先 B；A 失败时，b 仍在运行就先选空闲的 C，b 已停止则可选 B。

插件通过 DSH 请求头扩展点接收会话标识，并从 DSH 的会话投影读取当前轮次。内部会话摘要仅发给插件本机路由，渠道占用仅存内存。旧宿主缺少轮次信息时，每次请求按其它对话的负载选路；缺少会话标识或运行状态时，按在途请求均衡。

DSH 自动生成或更新标题时，按宿主声明的 `purpose: "session-title"` 识别辅助请求：不计入对话占用，不覆盖原会话保留的渠道，普通错误也不将渠道移到全局队尾；本次标题调用仍按原有条件尝试其它可用出口。明确余额不足仍按当天停用规则处理，已有停用渠道也不会被标题请求选中。用途标记只在插件本机路由内使用，不转发给上游；仅使用 `low` 档位的正常对话仍参与均衡和失败排序。旧宿主未声明用途时沿用普通请求规则。

一般模型调用失败后，将当前渠道整体移到队尾，其余渠道保持相对顺序。例如 `Qoder → Trae → WorkBuddy` 中 Qoder 失败，之后变为 `Trae → WorkBuddy → Qoder`；再轮到 Trae 失败则变为 `WorkBuddy → Qoder → Trae`。实际队列包含全部渠道，并非只处理这三个。占用相同时采用这份顺序；本次请求失败后先尝试其它尚未尝试的渠道，再考虑同渠道另一个出口。除明确余额不足外，HTTP 400、401、403、499、其它上游错误、连接失败、首输出超时、HTTP 200 中的 JSON/SSE 错误及输出后断连都会后移；用户或 DSH 主动取消不调整。每小时成功刷新额度后恢复到期优先级，但刷新期间新发生的失败继续后移，余额不足的停用记录保持不变。不会为重排打断正在输出的请求，下一次选路采用新顺序。

明确余额不足时，当天停用该账号或未拆分的渠道，其所有模型和对话均跳过该出口。同供应商的其他账号继续参与选路。插件「渠道」页显示渠道名、账号短标识、停用原因和北京时间检测时间，可点击「恢复选择」提前恢复；再次返回余额不足会重新停用。恢复前发出的旧请求不会再次停用刚恢复的渠道。状态缓存中的账号标识使用哈希。

当前请求在可重试错误（402、404、408、429、500、502、503、504）、连接失败或明确余额不足时尝试下一个可用出口。余额不足通过错误代码或错误正文识别，适用于 HTTP 错误、HTTP 200 JSON 和 SSE 错误。指定账号无法提供当前模型且网关明确提示时也会换出口，普通 400 原样返回。单独的 402 不等同明确余额不足，不会因此全天停用。未识别为余额不足的 401、403、499 等也继续原样返回，但下一次调用会使用后移后的渠道顺序。开始交付内容后不在本次请求内重放，以免重复执行工具；所有出口均失败时返回最后一次上游错误。后续请求若没有未停用的渠道，直接返回 503 并提示在「渠道」页恢复，不再反复请求上游。

当天的失败后移、余额不足停用记录、到期排序和最近成功刷新时间保存在插件缓存 `channel-order.json` 中，重启后继续沿用，不写入或重排用户的模型清单。统一以北京时间每天 04:00 为新一天的开始，与电脑时区无关；此前沿用上一日的停用记录。04:00 后恢复全部渠道，在新一天首次调用前重新读取额度、恢复默认到期顺序；日内每隔一小时也会重新读取额度和恢复到期优先级。额度读取失败时保留已有顺序或退回清单顺序，不阻断模型调用，五分钟后有请求时再试；晚到的旧日期请求失败不会污染新一天的排序。

流式请求从连接开始最多等待 60 秒，直到首个文本、推理、工具调用或合法结束帧。仅收到 HTTP 200、空角色帧和心跳不算模型已开始回答，也不会重新计时；期限到达即取消上游并换出口。非流式 JSON 在同一期限内读取并检查模型错误。HTTP 200 流内的错误也按对应状态处理。开始交付内容后的长生成不受这个期限限制；之后若流报错或连接中断，一般失败后移渠道、明确余额不足则当天停用，均不在原请求内重放。DSH 或用户主动取消请求不算供应商故障。

合并条目的上下文和最大输出取已知最小值，视觉能力取并集；思考档位取各候选的并集，候选都没声明时按低 / 高 / 最大兜底。请求带了档位（`reasoning_effort` 或 `reasoning.effort`）时，只要有兼容出口，就跳过明确不支持该档位的出口，未声明能力的按可用处理；全部明确不支持时保留原有候选兜底。带图请求会跳过不支持图片的出口。能力筛选后采用全局渠道顺序，同渠道的多个候选保持清单相对顺序；不按倍率、token 单价或余额多少排序。

转发复用宿主本机 webServer，支持 Chat Completions、Responses、Anthropic Messages 和 SSE 流；Anthropic 同时接受 Bearer / `x-api-key` 并保留版本请求头。请求只接受本机来源和已保存凭据，视觉请求体上限 32 MiB。DSH 换宿主端口时保留旧的本机兼容监听，卸载插件时停止。开关往返会按同款修复默认模型、子代理白名单等 `{ provider, model }` 引用并去重；引用修复失败会单独提示，不掩盖已经完成的清单更新。

「按模型排序」按模型名称升序排列，同名模型再按供应商简称排列；「按供应商排序」先按供应商简称升序分组，再按模型名称排列。默认即为按模型排序，不再提供按 Magpie 目录顺序排列的「默认排序」。排序忽略大小写，数字按自然顺序排列（例如 Model 2 在 Model 10 前），空名称或无供应商的条目排在后面；键值相同的条目保留相对顺序。有搜索或分类筛选条件时只重排匹配模型，隐藏条目的位置不变。勾选、编辑内容和展开状态一并保留，点击「保存并同步」后保存新顺序。

「按模型分类」和「按供应商分类」都是下拉筛选器，选择后只显示当前类别的模型。「按供应商分类」按供应商简称筛选，没有供应商的条目归入「未指定供应商」。「按模型分类」按版本号前的品牌归纳系列，例如不同版本、不同供应商的 DeepSeek 都归入 DeepSeek，GLM-5.1、GLM-5.3、GLM-5v 都归入 GLM；也支持 Hy、Kimi、Step 等命名。标准、高级、智速模式、Beam、Big、browser、computer、explore 等非主流系列名、内部代号和实验名统一归入「其他」，不再分别占用下拉项。Seed 是豆包的内部系列名，与 `doubao-*` 和中文「豆包」开头的模型名（如「豆包 2.1 Lite」「豆包 2.1 Pro」）一起归入首字母大写的 **Doubao** 分类。未填写名称的空白草稿行也归入「其他」，下拉不再单独显示「新模型」分类（「新模型」只作为空白行在列表中的显示名）。列表中「其他」类模型默认沉到其余模型下面（已勾选的仍按置顶规则优先），只影响展示顺序，不改保存顺序。「屏蔽小上下文模型」提供「不屏蔽」「低于 200K」「低于 500K」三档，默认低于 500K，旧配置的开启或关闭状态保持不变。上下文已知且小于所选阈值的模型不在卡片列表显示（等于阈值或上下文未知的保留，K 按千计），只影响卡片显示，不改勾选、同步与自动路由；选项即时保存，批量勾选与排序只作用于当前可见模型。选择「全部模型」或「全部供应商」清除对应筛选。两种筛选可取交集，并可与搜索、排序和拖放组合使用；筛选只改变当前展示，不修改勾选、配置或保存顺序。全量同步后自动恢复全部类别。模型行右侧的上下文徽标在 100K 至 1M 之间按百 K 向下归档：1xxK 显示 `100K`、2xxK 显示 `200K`、3xxK 显示 `300K`，9xxK 统一显示 `1M`。例如 128000 显示 `100K`、262144 显示 `200K`、524288 显示 `500K`、983040 显示 `1M`；小于 100K 的常见档位（如 `32K`、`64K`）沿用原显示规则。精确值保留在悬停提示里；过滤、保存与写入 DSH 的仍是原始数值。

拖动六点手柄调整顺序时，其它模型会实时让出落点，松手后直接落位；拖出列表或取消拖动则各行滑回原位。手柄获得焦点时也可按 ↑ / ↓ 键逐个移动（有搜索条件时跳过隐藏模型）。排序、增删、展开和筛选后，各行从原位置平滑移到新位置；系统开启“减少动态效果”时不播放这些动画。

从 Magpie 同步时的顺序取决于清单是否被手动排过：

- **按模型排序**（默认）：同步后按模型名称自动排好。
- **手动顺序**：拖动排序、「按供应商排序」或只对部分搜索、分类结果排序后，清单标记为手动顺序（卡片显示提示）。此后「从 Magpie 同步」保留现有顺序：仍在目录中的模型按原位置排列，新模型按名称排在末尾，上游已移除的模型被删除。未搜索且未分类筛选时对完整清单点击「按模型排序」并保存，即恢复自动排序。

本分组逐模型默认选择已配置档位中的最高档，按 `off < minimal < low < medium < high < xhigh < max` 排序。例如 Step 的 `low, medium, high` 默认 High，Flash 的 `low, high, max` 默认 Max。手动选择的档位继续生效；未声明推理能力的模型不补默认值。

当前 DSH 的 llm-pi-ai 只提供 provider 级默认配置。插件在宿主现有适配器的 `resolveModel` / `prepareCall` / `stream` 接口上仅补充 `dsh-magpie` 路由的逐模型默认值，沿用同一套模型元数据与协议实现。已有 provider 和模型 ID 保持不变，其它分组不受影响；适配器重载时重新附加，停用插件时撤销。

「从 Magpie 同步」先用 `/api/hello` 核对身份，再完整读取并校验 `/v1/models`。每次点击都以 Magpie 当前可用目录替换整个清单：名称、上下文、最大输出、图片能力和思考档位跟随上游，顺序按「按模型排序」的规则自动排好；手动排过序时保留现有顺序，新模型按名称接在末尾（见下文「排序」）；按模型 ID 保留当前草稿中已有模型的勾选状态，新出现的模型默认不勾选；开启同步，并立即保存及更新 **Magpie** 分组。上游已关闭或删除的模型、本地手工添加或修改的模型都会被这次全量结果覆盖；上游目录合法为空时清空清单并移除分组。请求失败、目录异常或版本冲突时保留原配置；清单保存后 DSH 分组更新失败会明确提示，可再次同步。模型名称仍追加供应商简称，默认推理档位仍选最高档。上游档位中 DSH 不支持的值（例如 `none`）会被忽略，只剩 `off` 时视为不声明思考；上游最大输出不小于上下文时只省略该模型的最大输出，其余字段照常导入。

关闭「同步到 DSH」（立即生效），或取消全部模型勾选后保存，只移除本插件创建的 `dsh-magpie` provider；保存的清单仍可编辑。已引用该分组的会话需要重新选择可用模型。卸载插件遵循 DSH 的配置保留规则，需要移除分组时先关闭同步。

## 配置边界与 Key

- 固定插件行 ID 和 provider ID 都是 `dsh-magpie`，不会修改 Magpie 原生的 `magpie` / `magpie-responses` / `magpie-anthropic` 分组、其它 provider、默认模型或其它 profile。
- 模型写入经宿主 `configEditor`，按锁内最新配置合并；已被其他配置占用的同名 provider 拒绝覆盖。两个页面同时编辑时，旧页面保存或修改即时开关、选项均返回冲突并保留草稿，需要重新载入后操作，避免覆盖刚保存的清单。
- 模型列表默认空；同步到 DSH、自动路由与屏蔽小上下文均默认开启（空清单仍不会生成 provider）。手动点击「从 Magpie 同步」才读取上游目录；普通保存和插件启动沿用已保存清单，不定时读取上游目录。旧配置中显式保存的关闭状态保持不变。
- 本机 loopback 使用官方约定的 `magpie-dsh` 标识；它会写入凭据供 DSH 调用，但不算已保存的 Key，切到远程 Magpie 时也不会发出。远程 Magpie 需要有效的 gateway key；卡片保存到 DSH 凭据库的 `DSH_MAGPIE_API_KEY`，配置中只保存引用，状态接口不返回 Key。环境变量同名值优先且只读；输入框留空沿用已保存值。
- 调用协议可选 Chat Completions、Responses、Anthropic Messages；前两者使用 Magpie 地址下的 `/v1/`，Anthropic 使用根地址。修改协议或地址后保存会同步更新 provider。
- 清单保存成功但凭据或 provider 同步失败时，卡片明确显示失败原因；清单保留，修复后再保存同步。读取配置和检查连接不会发送推理请求。

配置示例（写在本插件行的 `config` 下）：

```yaml
syncEnabled: true
autoRoute: true # 同款模型合并路由，默认开启
hideSmallContext: true # 卡片列表屏蔽小上下文模型，默认开启；false 表示不屏蔽
smallContextLimit: 500000 # 屏蔽阈值，可选 200000 / 500000，默认 500000（K 按千计）
hideNonVision: false # 卡片列表只显示支持图片输入的模型，默认关闭，不改勾选或同步
baseURL: http://127.0.0.1:3425
api: openai-completions
models:
  - id: workbuddy-ai/deepseek-v4.1-flash
    name: DeepSeek V4.1 Flash
    enabled: true
    contextWindow: 1000000
    maxTokens: 128000
    input: [text, image]
    reasoningEfforts: [low, high, max]
```
